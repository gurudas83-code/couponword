## Delivered implementation
1. All **40** consecutive ₹5,000 range buttons and guided-search options, from ₹0–₹2 lakh, use the same existing strict search parser. New options reside under collapsible “More ₹5k bands” so the hero remains compact. No new recommendation engine.
2. `scripts/build_price_evidence_coverage.py` reads the existing source files offline and exports `price-evidence-232.json`, with one entry per core model, source type, exact recorded RAM/storage/color where observed, historical date/source URL, and a 103-model verification queue.
3. `test_price_evidence_coverage.py` checks 232-model reconciliation, exact variant gates, missing evidence and the strict band partition. GitHub Research quality workflow retains the JSON evidence artifact for review.
4. Browser tests click the budget buttons and guided Apply controls; no third-party paid provider calls are made by the QA.

## Important publication limits
- Do not show unverified historical observations as live prices, sale discounts or official retailer offers.
- Never guess missing model prices or infer the price for a different RAM/storage/color configuration.
- Keep `purchase_eligible=false`, `live_price_verified=false`, `ranking_weight=0` for every record generated by this audit.
- Current Render `CW_QUICKCOMMERCE_DAILY_CAP=1` is a process-local limit, not a provider-side hard billing budget. Do not automate 103 billed requests until provider-side spending constraints, quota and explicit operational authorization are verified.
- Data is a **snapshot**, not a measure of active Indian stock, and Google indexing requires separate Search Console evidence.
