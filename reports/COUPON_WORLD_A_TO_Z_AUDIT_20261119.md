# Coupon World — Source-first A-to-Z audit and remediation register
Date: 19 November 2026 (India). Base: main commit 71654ebfc60090f1d1d9b2d5d979b6f7aaf839f5.
Scope: homepage HTML/CSS/JS, 122 tracked HTML source files (including 105 legacy product pages), research and store-data inputs, static publishing pipeline, curated mobile/TV/earbud pages, technical SEO quality gates, Render service and live request logs, and public Google/Amazon/Flipkart guidance.

## Evidence limits
- This is a source-code, data, publisher and API audit, not a claim of having visually inspected each generated public URL in a real browser. The published Pages artifact is generated by scripts/build_public_pages.py, so the 122 source HTML files are NOT the entire live page inventory.
- The search service used for this audit could not independently open coupon-world.in, and limited search results did not surface its pages. Neither outcome measures Google indexing, Google Search Console traffic, or uptime.
- Exact page-level rendering, viewport, accessibility, redirect, and sitemap checks require the browser/SEO GitHub Actions and an actual deployed Pages artifact. Search Console property data must come from the owner-authorized property.
- Static source catalogue and generated enriched mobile catalogue have different metadata. Do not pass raw source counts off as measured live-page counts.
- All store/API price data below are third-party research observations, not official retailer checkout quotes or authorized affiliate product-feed data.

## Positive existing safeguards (preserve them)
A. Homepage index/follow, self canonical, title/description, WebSite SearchAction JSON-LD and direct links to guide hubs already exist (index.html).
B. robots.txt permits crawling and advertises https://coupon-world.in/sitemap.xml.
C. Generated-publication pipeline reconciles sitemap canonicals, prunes noindex/retired URLs, validates internal links and maintains product publication gates (scripts/build_public_pages.py, python/publication_policy.py).
D. 977 historic keyword/answer routes are retired by policy, not blindly regenerated (data/retired_public_routes_20261106.json). Two thin generic static SEO files are deliberately deleted in the actual artifact.
E. Site source-backed specifications distinguish manufacturer claims, independent tests, and dated retailer observations; price weight in quality ranking is 0%.
F. Exact retailer URL and SKU/variant checks, disclosure and image/license restrictions already exist. Do not bypass these gates to increase Buy-button counts.

## Findings — itemized and status

### P0: correctness, budget, public trust
1. **Paid API called merely by opening saved-price panel** — Confirmed in assets/retailer-observations.js, show(). It spent quota without a separate user decision. **PATCHED IN BRANCH:** an explicit live-check button is now required.
2. **Changing selected RAM/storage configuration could trigger another paid lookup** — Confirmed in same JS. **PATCHED IN BRANCH:** changing variant refreshes saved display only and invalidates the prior live response.
3. **New manufacturer-source phones returned unknown_model/404 in paid API** — Confirmed via Render logs (OPPO and other newly introduced keys) and python/paid_api_live_bridge.py catalogue() which previously included only 232 core phone entries plus 40 TV/earbud entries. **PATCHED IN BRANCH:** include existing eight market-source and recent manufacturer-reviewed models in research-only lookup. Separate price authorization remains prohibited.
4. **Process-local paid-call budget can reset on server restart and cannot coordinate across workers** — Confirmed in python/paid_api_live_bridge.py. Render currently has CW_QUICKCOMMERCE_DAILY_CAP=1. **OPEN:** add provider-side hard budget and persistent shared quota before scaling; do not make unlimited calls.
5. **429 responses under the deliberately restrictive one-call budget** — Seen in Render logs. **EXPECTED GUARD, NOT RETAILER OUTAGE:** show clear quota message; consider higher cap only when billing control is independently verified.
6. **Not all models have fresh exact-store prices** — Source observation snapshot dated 17 Nov: 154 model entries, 800 listed configurations, 887 retailer rows (Flipkart 725, Amazon 153, Croma 9). Not every row is a simultaneously fresh, verified SKU. **OPEN:** prioritize exact model/region/RAM/storage evidence for Top 30; never fill missing prices from guesses.
7. **Pincode 110001 is fixed for live third-party requests** — python/paid_api_live_bridge.py. **OPEN:** clearly label observation as Delhi-pincode-specific; a future pincode chooser needs validated supported inputs, rate limits and provider terms.
8. **API observations are not retailer-authorized checkout offers** — Publication_authorized and purchase_eligible are false in the bridge response. **PRESERVED:** do not mark a third-party observed amount as official, guarantee stock or generate fictitious Merchant Offer structured data.
9. **Automatic Buy buttons for all 232 models would be misleading** — Many catalogue cards have only search destinations, not separately authenticated exact-variant store listings. **OPEN / CONTROLLED:** render Buy-at-store only for links meeting reviewed identity and legal purchase-eligibility rules. For others retain honest Search Amazon / Search Flipkart / Search Croma choices.
10. **No proof of current Google impressions, clicks, indexing exclusions or average position** — No connected Search Console dataset was available to this audit. **BLOCKED ON DATA ACCESS:** retrieve GSC Performance and Page Indexing reports, especially impressions vs clicks vs Crawled/Discovered-currently-not-indexed.
11. **Live Pages domain response / visual rendering not independently fetched in this audit** — Public web open failed; backend Render was separately verified Live. **OPEN:** verify homepage, navigation, mobile/TV/earbud hubs, canonical headers and JS/no-JS rendering from a real web browser and Pages build artifacts.
12. **No persistent freshness operations for the whole catalogue** — Six-hour freshness logic is not the same as a live operational refresh schedule, and free Render has ephemeral filesystem. **OPEN:** rate-controlled, authorized, durable observation scheduling with provider billing constraints.
13. **Thin legacy /buying-guides.html duplicated the better /guides/ hub and lacked a canonical** — Confirmed tracked source and explicit inclusion in PUBLIC_FILES. **PATCHED IN BRANCH:** noindex/canonical/meta refresh to curated /guides/; test added.

### P1: frontend flow, content and discoverability
14. **Homepage prioritization is busy** — Hero plus multiple action buttons, seven nav destinations, additional SEO links, detailed filters and old catalogue sections. **OPEN UX:** place a single primary Find Phone action, a secondary Compare action, then progressive advanced controls. Test with real mobile visitors; preserve crawlable guide links.
15. **Price type and timestamps need consistently prominent labels** — Dated budget reference, historical saved observation and just-checked paid observation are distinct states. **PARTIAL:** source distinguishes them. **OPEN:** verify card/SEO/mobile viewport labels and cached/expired clarity in Chromium.
16. **JavaScript-driven catalog results are not a substitute for crawlable model routes** — Source HTML contains interactive inventory placeholders. The publisher creates static source-backed phone pages and linked hubs. **PARTIAL / VERIFY:** test no-JS HTML, heading structure, per-model navigation and internal link depth in the exact produced artifact.
17. **Raw catalogue vs publication metrics risk being confused** — Source file has 232 model_cards and only 40 raw cards with nonempty inline specification objects; publishing enrichment and previous snapshots cite more. **OPEN:** publish separate source/catalogue/build/live metric definitions and validate all counts by build manifest, not visual marketing copy.
18. **Camera information can mislead without evidence tiers** — Megapixels and OIS describe hardware, not actual low-light quality, skin tone, video or shutter reliability. **GUARD PRESENT / OPEN CONTENT:** attach comparable independent test methodology and India-unit caveats before subjective best-camera claims.
19. **Battery capacity is not measured endurance** — A 5000–10000 mAh capacity figure does not establish screen-on time or battery aging. **GUARD PRESENT / OPEN CONTENT:** keep independent endurance results separate and disclose usage conditions.
20. **Gaming chipsets do not establish sustained performance** — CPU/GPU model, RAM and advertised refresh rate are not observed FPS, thermals or throttling. **GUARD PRESENT / OPEN CONTENT:** allow performance comparisons only with comparable tested-unit evidence.
21. **Software support claims need dates and region** — Promised updates are not remaining support years. **OPEN:** verify launch, end-of-support, India region and source checking date before asserting longevity.
22. **Top 30 model-first purchase path is incomplete** — A user wants model page, exact RAM/storage/color, technical table, verified retailer options and comparison in one clean path. **PARTIAL / OPEN:** preserve existing guided search, comparison and source links; focus on Top 30 with explicit unavailable states.
23. **Real product photography coverage and rights are incomplete** — TV/earbud catalogue has 40 rows and zero image_publish_eligible=true; 20 rows explicitly NOT_CLEARED_DO_NOT_PUBLISH and 20 lack that property in source snapshot. **OPEN / LEGAL:** no provider photo import until model-match, reuse license and attribution are documented.
24. **TV and earbuds coverage is research-first, not three-store commerce-ready** — Exactly 20 TVs and 20 earbuds in source snapshot. 19 have at least one reviewed exact retailer link; Croma exact IDs and retailer quote coverage are incomplete. **OPEN:** manufacturer code, region, panel/audio features and legally sourced image/retailer IDs before Buy.
25. **Old static generic keyword pages exist in the Git checkout** — Two old pages advertise generic best-earbuds/best-smartwatch comparisons without specific substantive reviewed winners. **ALREADY FILTERED OUT by python/publication_policy.py** in generated Pages artifact; do not incorrectly report them as indexed live URLs.
26. **All 65 approved technical legacy product pages must be treated as separate from the 232 research models** — Existing test_seo_index_hygiene.py expects 65 published product pages with noindex unless true offer evidence. **GUARD PRESENT:** do not re-add 105 unreviewed legacy pages or mix non-tech products into the current niche.
27. **Crawl and mobile UI regressions need release checks** — Browser QA exists for 390px/1440px, responsive overflow, retailer history and comparison. **OPEN TO CONFIRM PR GATES:** run full Actions before merge.
28. **User-feedback/contact is via GitHub issue rather than a general accessible help route** — The About page links to repository issues. **OPEN UX:** consider a public feedback option with moderation/privacy policy before collecting personal data.
29. **Site name versus focus creates some expectation mismatch** — Coupon World sounds like discount codes, while the product now prioritizes phone research. About page explains this. **PARTIAL:** make home title/description and navigation immediately clarify independent tech research; do not introduce unverified coupons solely to match name.
30. **Privacy and analytics transparency require a separate review** — The homepage includes a Google Analytics tag, but audited source navigation did not establish a complete public privacy/data-usage notice. **OPEN LEGAL REVIEW:** confirm actual collection, consent mechanism and current applicable law before claiming full compliance or publishing an inaccurate policy.

### SEO / Google-specific decisions
31. **Google indexing is not guaranteed by a green sitemap or Rich Results test.** Google Search Console URL Inspection and Page Indexing reasons determine which routes Google actually crawled and indexed. Structural source checks already exist; operational measurement is missing.
32. **Do not use Merchant Listings as an SEO shortcut on an affiliate comparison page.** Google's merchant-listing guidance says the shopper must be able to purchase on the page; links to other retailers alone are not sufficient. Product-snippet/editorial markup, where applicable, must truthfully match visible page content and avoid fabricated reviews/ratings.
33. **Adding 500 thin SEO pages is not a growth fix.** The current policy deliberately retired 977 keyword pages. Expand only reviewed topics with unique value, source links, real comparison caveats, useful model availability and indexable internal links.
34. **Core Web Vitals and search CTR are unmeasured in this audit.** Need real PageSpeed/CrUX field metrics and GSC query/page CTR before asserting a 0.3-second experience or diagnosing snippet failures.
35. **Searchable editorial comparisons need more original reasoning.** Existing specification pages are useful, but make user-specific trade-offs explicit: camera hardware versus tested images, battery mAh versus tested endurance, gaming hardware versus observed sustained performance, warranty/region and update policy. Do not invent hands-on tests.

### Affiliate, rights and coupon API
36. **QuickCommerce search API is not a coupon-code syndication licence.** Don't publish a coupon as verified unless it has a permitted partner feed, terms, coupon code/deal scope, validity, exclusions and an owner-verified destination.
37. **Amazon Associates requires its affiliate disclosure and restricts use of Program Content/imagery.** The About page already states the Amazon Associate disclosure; verify it is conspicuous wherever required. Historical tagged links are not proof of active affiliate approval.
38. **Flipkart's affiliate content terms restrict use of affiliate-derived text/photos, including using content to send sales elsewhere.** Third-party API access does not grant retailer image syndication rights. Don't import QuickCommerce image URLs as public product photos.
39. **Affiliate/sponsored links need appropriate attribution and rel flags.** Existing Amazon tagging and sponsored link support are present; verify generated retailer links and model pages before declaring each compliant.
40. **All prices shown via the API must identify source, checking timestamp, selected variant, pincode, stock observation and retailer checkout caveats.** Avoid structured data describing current checkout price unless a separate legal and freshness gate is satisfied.
