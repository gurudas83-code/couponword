# Coupon World full website audit\n\n**Audit date:** 2026-10-29\n**Repository:** `gurudas83-code/couponword`\n**Audited state:** `0d418bc303df46ab3f489e28ffee2ed77f53b620` on `main`\n**Scope:** GitHub Pages artifact, homepage frontend, public data, Render API contract, deployment workflow, SEO paths, mobile layout rules and safety regressions.\n\n## Executive result\n\nThe P13.1 research preview is now publicly present and data-safe. The static homepage and its 10 frozen research variants are reachable. The live shopping backend is not healthy: both `/health` and `/api/recommend` at `couponword.onrender.com` timed out repeatedly during this audit. This means the public deal shell can load while AI recommendations and live shopping results remain unavailable.\n\nThe frontend also presents a mixed experience: a research comparison, live shopping claims and a deal wall are placed on one long page, while the published deal data contains no current prices and no eligible purchase CTAs. A published `/guides/` link is broken because the Pages allow-list omits the `guides/` directory.\n\n## Evidence collected\n\n| Area | Result |\n|---|---|\n| Homepage | HTTP 200; static HTML 16,277 bytes; P13.1 CTA and preview section present |\n| Research JSON | `PUBLIC_TECHNICAL_RESEARCH_PREVIEW`; 10 products; 10 unique canonical IDs; commerce fields safe |\n| Render `/health` | Repeated read timeout at 12 seconds |\n| Render `/api/recommend` | Repeated read timeout at 12 seconds |\n| `coupons.json` | 105 rows; 74 active rows; 31 rows without `active`; 105 without price; 75 without image; 46 without ASIN |\n| Offer eligibility | 0 rows have `cta_eligible: true`; the field is absent from the source rows |\n| Public guide path | `/guides/` returns 404; `/buying-guides.html` returns 200 |\n| Sitemap | Advertises `/guides/` and three guide child URLs that are not in the Pages artifact |\n| Focused regression tests | 29/29 PASS |\n| Pages workflow | Successful run for `0d418bc`; artifact deployment is working |\n\n## P0 blockers\n\n### 1. Live recommendation backend is unavailable\n\n`app.js` sends non-empty searches to `https://couponword.onrender.com/api/recommend`. The service did not return `/` or `/health` within two consecutive 12-second probes, and the recommendation route also timed out. The frontend has no `AbortController` timeout, retry action or explicit degraded-mode panel, so a visitor can wait indefinitely for a result.\n\n**Impact:** Search, AI recommendations, ranking explanations and the live shopping path cannot be trusted as available.\n\n**Fix plan:** inspect Render service status and logs; confirm the start command and worker configuration; add a bounded request timeout and retry UI; make `/health` report dependency readiness separately from process liveness; add a lightweight cached response path for repeated read-only queries; then run live smoke probes from CI.\n\n### 2. Deal wall is populated with non-buyable rows\n\nThe public `coupons.json` has 105 records but no current prices and no `cta_eligible: true` records. The frontend does not filter `active` rows before rendering, so 31 rows without an active flag can still appear. Cards are labelled as deals while their buttons resolve to “Offer verification unavailable.”\n\n**Impact:** The primary shopping surface looks populated but cannot complete a verified purchase flow and may show stale or inactive entries.\n\n**Fix plan:** enforce a versioned source schema; filter `active === true`; require current price, availability, freshness and verified retailer mapping before rendering a deal CTA; show research/catalogue rows in a separate non-shopping state; add CI counts and freshness thresholds.\n\n### 3. Published buying-guide links are broken\n\n`index.html` links to `/guides/`, and `sitemap.xml` advertises `/guides/` plus three child pages. `scripts/build_public_pages.py` copies `buying-guides.html` but does not copy the `guides/` directory. The live `/guides/` path returns 404.\n\n**Fix plan:** either add the approved `guides/` directory to the public allow-list and verify all child pages, or change the homepage and sitemap to the existing `buying-guides.html` route. Add an internal-link checker to the build.\n\n## P1 frontend and product issues\n\n### Information architecture\n\n- The hero promises verified mobile picks, the AI panel, research comparison and deal wall in one scroll path.\n- “Mobile Picks” navigates to the generic AI recommendation panel, not the verified mobile comparison.\n- The research section renders ten detailed cards directly on the homepage; a compact teaser plus a dedicated comparison route would reduce cognitive load.\n- “100% Affiliate ready” is not a customer benefit and competes with the primary action.\n- “Today’s Biggest Price Drops” and “Browse Hot Deals” are misleading when the public data has no current prices.\n\n### Frontend reliability\n\n- `API_BASE_URL` is hard-coded to the Render hostname; there is no environment or health-aware configuration.\n- Fetch requests have no deadline, abort handling or retry button.\n- Rapid searches can race: an older slow response can overwrite a newer query because no request sequence or abort controller is used.\n- `coupons.json?v=Date.now()` disables useful CDN/browser caching on every page load.\n- Dynamic rendering relies heavily on `innerHTML`; current escaping tests pass, but a schema validator and safer rendering boundary would make future data changes safer.\n\n### Mobile and accessibility\n\n- The responsive CSS has mobile breakpoints and the focused responsive tests pass.\n- There is no skip link, no visible mobile navigation menu, and no `prefers-reduced-motion` handling for smooth scrolling.\n- Dynamic recommendation and deal states need clearer `aria-live` status, retry controls and focus movement after errors.\n- A dedicated visual smoke matrix is still needed for 320px, 375px, 768px and desktop widths.\n\n### SEO and content quality\n\n- The Open Graph title/description describe “Hot Online Store Deals” while the document title and page hero describe verified mobile picks.\n- No favicon, `og:image` or Twitter card metadata is present in the homepage head.\n- The sitemap contains broken guide URLs.\n- Source data has 75 missing images, 46 missing ASINs and a number of legacy rows with incomplete status fields.\n\n### Security and privacy\n\n- API CORS is explicitly restricted to the production site and approved loopback origins; this is good.\n- Public artifact filenames are allow-listed and action SHAs are pinned; this is good.\n- The Pages workflow checks forbidden filenames but does not scan the contents of every allowed JSON/HTML file for private evidence or secrets.\n- The homepage loads Google Analytics and Cloudflare analytics through external scripts without a documented consent/privacy flow.\n- `safeLink` checks URL protocol but does not restrict affiliate destinations to an allow-list of approved retailers.\n\n## P2 maintainability and operations\n\n- `style.css` contains an older dark theme plus a later `clean-ui` override, making visual changes difficult to reason about.\n- `app.js` is a large mixed data-loading, rendering, analytics and ranking-display module.\n- The backend deployment contract is not documented in the repository: there is no `render.yaml`, Procfile or recorded start command.\n- The daily coupon bot has write permission and pushes `coupons.json` without the same public-artifact and data-quality checks used by Pages.\n- There is no published SLO for backend latency, stale-data handling or deployment rollback.\n\n## Recommended implementation order\n\n### Phase 1 — restore dependable operation\n\n1. Resolve Render service startup/health timeout and document the deployment command.\n2. Add API deadline, retry and degraded-state UI.\n3. Add an API health smoke test to CI and a production probe after deployment.\n4. Validate the recommendation response contract against a real request.\n\n### Phase 2 — make the shopping surface truthful\n\n1. Define the coupon row schema and freshness rules.\n2. Filter inactive/invalid rows before rendering.\n3. Show only verified current offers as purchase cards.\n4. Move research/catalogue rows into a labelled non-shopping section.\n5. Add data-quality counts to the bot and Pages workflows.\n\n### Phase 3 — repair navigation and information architecture\n\n1. Fix or deliberately redirect `/guides/` and all child guide URLs.\n2. Change “Mobile Picks” to the mobile research comparison route.\n3. Keep a compact homepage research teaser and put the full 10-variant comparison on its own page.\n4. Reduce duplicate deal/category sections and make the primary visitor action unambiguous.\n\n### Phase 4 — mobile, accessibility and SEO\n\n1. Add skip link, mobile menu, focus states, reduced-motion support and accessible async states.\n2. Add consistent title/description/Open Graph metadata, favicon and valid sitemap URLs.\n3. Run visual and link smoke tests at the four target viewport sizes.\n\n### Phase 5 — security and operations\n\n1. Add content scanning to the public artifact check.\n2. Use retailer host allow-listing for outbound purchase links.\n3. Document analytics/privacy behavior.\n4. Add rollback and freshness monitoring for the coupon bot and Render service.\n\n## Safe items that should remain unchanged\n\n- Frozen P13.1 canonical IDs and the 10-variant research data.\n- Manufacturer evidence, labelled model-level battery/camera evidence and official source provenance.\n- Ranking formulas and technical/research gates.\n- Price, stock, publication and purchase eligibility gates.\n- Private Product DNA and internal evidence stores.\n\n## Audit conclusion\n\nThe Pages deployment and P13.1 static research data are healthy. The product is not ready for a broad frontend redesign or additional mobile expansion until the Render backend availability and the deal-data contract are repaired. The next safe action is Phase 1: restore and prove the backend, then apply the data/navigation fixes with a reviewed patch and mobile smoke matrix.\n
